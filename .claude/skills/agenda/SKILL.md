# アジェンダ管理の手順

正本は1か所だけ: **ロードマップ・アクションプラン_v2(Googleスプレッドシート、04_進行管理/ロードマップ/)の「週次ワークプラン」タブにある「週次定例アジェンダ」行**。会議ごとのdocxは作らない(対外に配るときだけこの行から出力する)。

## 絶対のルール

1. **アジェンダ行に入れてよいのは「3人で決めること」だけ。** 事実確認・報告・作業はWBSタブのタスクか、定例の案件進捗枠へ。混ぜると差し戻しになる(実例: 「松山ケンイチ主演は確定か」は議題ではなく近藤への確認事項)
2. **書き込みはHIL。** 変更一覧(セル・変更前後)を見せてOKをもらってから書く
3. **行位置を決め打ちしない。** 書き込み前にA列を読んで「会議日程」「週次定例アジェンダ」「マイルストーン(全体)」の行番号を特定する(レイアウトは動く。1行ずれ事故の実例あり)
4. 「決めること」の各行は対応するI-ID(SSOT論点台帳)を頭に付ける。IDの定義・採番・閉じ方は **ontology スキル**を参照
5. タスクを足すときは期限必須。担当は ①発言・担当列の根拠 ②役職(三嶽=CEO兼CBO、杉山=COO・CSO、近藤=CCO) ③要確認 の順で決める

## 書き込み方法

ブラウザ操作ではなくSheets APIを使う(衝突しない)。`889_Claude_Code/tools/roadmap_tasks.py` の `service()` を流用:

```python
sys.path.insert(0, '889_Claude_Code/tools')
from roadmap_tasks import service
svc = service()  # SID = 1vpSzEOgrqW6fRQJOskZyM5piHf0fNwhC5u3C9w1DGN8
```

## 議題の集め方(定例前)

1. 「週次定例アジェンダ」行のその週のセル(既存の正本)
2. SSOT「論点台帳」— 討議中・未討議で期限が近いもの
3. SSOT「分岐点と期限」— 2週間以内のもの
4. 前回議事録の継続協議・宿題
5. Slackダンプ(888_Inbox)の「決めたい」系発言

集めたら「決めること」だけに絞ってセルを更新(HIL)。**件数の上限は設けない。AIは議題を減らさない・繰り越さない**(全件を当日の議題に載せる。2026/8/29に「6件まで、あふれたら翌週へ」のルールを三嶽の指示で廃止。実例: I-060・I-024・I-034を勝手に9/5送りにして差し戻し)。束ねて見やすくするのはよいが、落とすのは3人。

## 進行用HTML(会議で映すビュー)

「HTMLにして」「進行用を作って」と言われたら、セルの内容から1枚のHTMLを作る。正本はあくまでシート行で、HTMLは派生のビュー(シート行を直したら作り直す)。書く前に ng-words スキルを読む。フォントはMeiryo UI系、文字は12px未満禁止。Artifactで公開して渡す。

ページの並びは固定。上から:

1. **ヘッダー**: 日時・参加者・議題数
2. **今日のアジェンダ** — 議題一覧(番号・タイトル・時間枠・PIC)。各議題へのページ内リンクを張る
3. **情報共有(前回定例以降)** — 見出しは「情報共有」。中は2段: 先頭に「決定事項 UPDATES(前回定例以降に決まったこと・変わったこと)」、次に「動き(決定ではない報告)」。UPDATESには前回以降の新しい確定と、確定→討議中に戻った変更(期限の不成立など)を入れる。確定済みセクション(下記)には前回より前の決定だけを置き、同じ決定を両方に書かない(実例NG: ロゴ発注確定を両方に書いて差し戻し)
4. **ロードマップ** — 自作しない。`04_進行管理/ロードマップ/ロードマップ_YYYYMMDD.html`(最新)の中のSVGをそのまま埋め込む(横スクロールの箱に入れ、min-width 1210px)。古ければ先に `roadmap_gen.py` で再生成
5. **確定済み(今日の議題に関わる決定)** — 必ず置く。論点台帳の「確定」から、当日の議題に関係する決定だけをI-ID・決定内容・決めた日つきで列挙する。末尾に「確定を変えるときは、この場で覆さず、論点を討議中に戻して変更依頼(CR)を切る」の一文を固定で入れる。理由: 近藤は決まったことを忘れがち、三嶽は決まったことを覆されるのが大嫌い。蒸し返しをここで止める
6. **議題(全件)**: その週の「決めること」を全部載せる(件数上限なし。関連する論点は束ねてよいが、AIの判断で落とさない・翌週へ回さない)。各議題に 時間枠・PIC(「口火」ではなくPICと表記)・「決める問い/今の案(たたき台)」の表・「決まればクローズ: …」の行。経費・数字の議題には根拠の表を小さく添える(経営の数字は図にせず表と文字で。ng-wordsの大原則)
7. **この先の会議と決めること(向こう4週間)** — 週レンジ(8/31〜)ではなく会議の日付ベース(9/5(土)15:00 定例、など)で書く。各定例の下に「決めること」セルの中身+今日からの繰り越しを載せる。定例以外の日付つき会議(レビュー会など)もここに
8. **週が決まっていない未決の論点(全件)** — 論点台帳の討議中・未討議のうち、どの定例にも割り当てていないものを全件、期限が近い順の表(論点・期限・担当)で。「大事なもの」の選別はAIがしない(選別基準を持たないため全件載せて漏れゼロを優先し、絞るのは3人)
9. **直近のタスク** — 論点と混ぜず別の表。WBSの未完了タスクを次の節目(登記申請など)まで、期限順・超過を先頭に(タスク・期限・担当)。今日の議題に対応するものは「→ 今日の議題n」と書く
10. **出どころ**(フッター)

作る前にSSOTの鮮度を確認する: `ssot_tool.py dump` を実行してスナップショットを取り直し、論点台帳は必ず最新スナップショットから読む(古いスナップショットで作ると採番済みのI-IDを見落とす。実例: I-078・I-079)。「決めること」セルも作る直前に読み直す(他のセッションが更新していることがある)。ページに「議題の出どころ」のセクションは作らない(2026/8/29に不要と指示)。

実例(この構成・配色に合わせる): このスキルの `templates/agenda_example_20260829.html`。時間枠とPICはHTMLだけに書き、シートのセルには入れない。

## 会議のあと

- 決まったこと → SSOT論点台帳の該当行を確定に(ssot-updateの手順・HIL)
- 決まらなかったこと → 翌週のセルへスライド
- 議事録の処理は inbox スキル
