# Inboxの処理

共有ドライブの `888_Inbox/` に入ったファイルを片付ける。Inboxの中は2つに分かれている。

- `文字起こし/` … 会議の録音・文字起こし・自動サマリー。議事録の草稿を作る対象
- `素材/` … 仕分けさせたいファイル。行き先の表に従って棚へ移す

直下に置かれたファイルは中身を読んでどちらかとして扱う。契約書や企画書のような行き先が明らかなものは、ユーザーが直接棚に置いている前提。

**処理が終わったファイルはInboxに残さない。** 文字起こしの原文は、作った議事録草稿と同じ会議フォルダ（`05_会議/<会議体>/<日付>_<会議名>/`）へ移す（8/11の議事録・アジェンダ・Grainサマリーが同居しているのと同じ形）。素材は行き先の棚へ移す。Inboxに残ってよいのは、判別できなかったものと `処理ログ.md` だけ。

## 無人実行(定期タスク inbox-auto-sort から呼ばれた場合)

30分ごとの自動実行では、大原則2の「承認を得てから」を次に置き換える。行き先の表に明確に一致するものだけ承認なしで移動し、少しでも迷うものは残す。SSOT.xlsxは書き換えない。結果は `888_Inbox/処理ログ.md` の先頭に日時付きで追記する。

## 大原則

1. **AIは候補しか作らない。** SSOTも既存文書も直接書き換えない。決定事項も宿題も、追加候補のファイルとして出すところまでが役割
2. **Inboxのファイルを削除しない。** 移動は提案して、承認を得てから実行する
3. **判別できないものはInboxに残す。** 迷ったら動かさない
4. **日本語を書く前に `ng-words` スキルを読む。** 議事録も候補ファイルも対象

## 手順

### 1. 中身を見る

Inboxの全ファイルを一覧し、それぞれの種類・サイズ・更新日を出す。中身を読まないと判別できないものは読む。

### 2. 行き先を判定する

| 中身 | 行き先 |
|---|---|
| 会議の文字起こし、録音の自動サマリー（Grain等）、会議メモ | 議事録の草稿を作る（手順3へ）。原文は `05_会議/<会議体>/<日付>_<会議名>/`（会議体は 週次定例/四半期定例/年次定例/臨時/社外打ち合わせ。社外は 日付_相手_件名） |
| アジェンダ | `05_会議/<会議体>/<日付>_<会議名>/` |
| 企画書、脚本、プロット、予算表 | `10_制作/企画開発/<作品名>/企画書 or 脚本/`（IDは付けない。実制作が決まった作品は 10_制作/実制作/ の下） |
| 契約書、覚書、規程 | `00_ガバナンス/契約/` |
| 資金計画、出資条件、株主関連 | `02_財務・資金調達/資金計画/` |
| 作家との契約、作家リスト | `12_作家・エージェント/` |
| ラジオの台本、ゲスト資料 | `13_自社メディア/`（初めてファイルが出たときに作る） |
| ロゴ、画像、Web素材 | `89_作業中/<自分の名前>/ブランド作業中/` |
| 外部から受け取ったまま手を入れないもの | `06_資料/受領資料/` |
| 判別できないもの | Inboxに残す |

移動前に、行き先に同名または同内容のファイルがないか `md5` で確認する。同じものがあれば移動せず、重複として報告する。

### 3. 議事録の草稿を作る

会議の記録があれば、`05_会議/<会議体>/<日付>_<会議名>/議事録_<会議名>_<日付>_草稿.md` に書く。形式は8/11作戦会議の議事録に合わせる。

```
Narratier <会議名> 議事録

日時: 2026年8月11日(月) 14:04〜16:11(2時間7分)
参加: 三嶽さん、近藤さん、杉山さん(ロンドンからリモート)
記録: 自動文字起こしをもとに作成(2026/8/12)。音声の話者判定が乱れていたため、発言者は内容から補正した。

1. 決定事項
   番号付きで並べる。1項目1決定

2. 案件の整理
   表（案件 / 規模 / 状況 / 位置づけ）。動きがなければ節ごと省く

3. 継続協議(次回以降)
   結論が出なかったもの

4. 宿題
   表（担当 / 内容 / 期限）

5. 次回
   日時と、招待の送付状況
```

書き方のルール。

- **決定事項に入れるのは、結論が出たものだけ。**「〜という案がある」「検討する」は3の継続協議に回す
- **数字は原文のまま書く。**丸めない。「2億」を「約2億」に変えない
- **話者が曖昧なときは内容から補正し、補正したことを冒頭の「記録」欄に書く**
- 人名は姓で統一する（三嶽 / 近藤 / 杉山）。議事録では「さん」を付ける
- 草稿は `.md` で作る。内容が固まってから `docx` スキルで `.docx` に変換する。体裁を先に作ると直しが二度手間になる

### 4. 決定と宿題を抽出する

同じフォルダに `SSOT反映候補_<日付>.md` を作る。SSOTのシート構成に合わせた形で書く。

```
## 論点台帳の更新候補(既存の論点は行を書き換える。新規はI-ID採番案を付ける)
| I-ID | 論点 | 状態(未討議/討議中/確定) | 今の答え | 決めた日・場 | 担当 | 期限 |

## 既存の記載と食い違うもの
| シート | 現在の記載 | 議事録の内容 |

## 案件シートへの追加・更新候補
| 案件 | 種別・規模 | 状況 | 位置づけ |
```

判定のルール。

- **確定にするのは、その場で決まったこと。**方針の変更はSSOTの「方針」シート側の更新候補にも並べる
- **宿題は担当と期限をセットで書く。**期限が出ていなければ「未定」と書く。勝手に置かない
- **すでにSSOTにある内容は候補に入れない。**先にSSOTを読んで突き合わせる
- **食い違いは必ず出す。**議事録にあってSSOTにない決定は、反映漏れとして「食い違い」に並べる

### 5. 報告する

処理の結果をまとめて出す。

- 移動したファイルと行き先
- Inboxに残したファイルと、残した理由
- 作った議事録の草稿と候補ファイルの場所
- 決定の候補が何件、宿題が何件、食い違いが何件

## SSOTの扱い

SSOTはドライブ直下の `SSOT.xlsx`。突き合わせるときは直接読む。編集前に `~$SSOT.xlsx` ロックが無いことを確認する。

反映そのものは人が行う。このスキルは候補を出すところで止める。

## やらないこと

- SSOTを直接書き換える
- Inboxのファイルを削除する
- 確認を取らずにファイルを移動する
- 議事録に、記録に無いことを書き足す
- 決まっていないことを決定事項として書く
