# Slack同期(①SSOT候補 → 差分 → ②スケジュール候補 → HIL)

作業ディレクトリ: ドライブ直下(00_Company_Core)。ツールは `889_Claude_Code/tools/`。

## 手順

1. **Slackクローリング** — `python3 889_Claude_Code/tools/slack_dump.py` を実行。古いスレッドへの新着返信も取得される(2026/8/19修正済み)。新着分が 888_Inbox に出る(state.jsonで差分管理)。出力が無ければ「Slackに新着なし」として3へ進む
2. **① SSOT更新候補** — 新着メッセージから拾う: 決まったこと(論点台帳の状態を確定へ)、事実の変化(案件・数字の更新候補)、新しい論点(論点台帳に未討議/討議中で追加)。既存の論点は行を増やさず書き換える形で出す。SSOTを読んで既載のものは除く
3. **SSOT確定とスケジュールの差分** — ②の前に必ずやる:
   - SSOT側: 「分岐点と期限」の期限、「論点台帳」の討議中・未討議のI-IDと期限、確定した論点が生むタスク
   - ロードマップ側: `python3 889_Claude_Code/tools/roadmap_io.py read WBS A1:H40`、同 90日アクションプラン、同 タスク候補
   - SSOTにあってロードマップのどこにも無いものが「漏れ」
4. **② スケジュール変更候補** — Slack由来のタスク + 3の漏れ。各行: 起票日/タスク候補/担当(案)/期限(案)/出どころ(SSOT T-xxx、Slack、議事録など)/状態=候補
4b. **原作・題材ネタ** — 映像化したい原作・題材の投稿(#01_企画の「原作モノリスト」スレッドなど)は`10_制作/企画開発/原作候補リスト.xlsx` への追記候補にする(列: 起票日/題名・題材/種別/作者・対象/言い出し/メモ/状態)
5. **HIL** — ①と②と4bを1つの表にしてユーザーに提示し、OKを待つ。**OKの前にSSOTにもロードマップにも書かない**
6. **反映(OK後)** — ①はssot-updateスキルの手順で(dump→編集→版上げ→dump)。②は承認されたものをWBSタブに直接入れる(ontologyスキルのID採番に従う)。「タスク候補」タブは廃止(2026/8/20)
7. 結果を1行でSlackの #00_corp_note に流してよいか、あわせてユーザーに確認する

## 守ること

- SSOT反映候補・Slackまとめのmdは `99_アーカイブ/Slack同期ログ/` に置く。`06_資料/関連資料` には入れない(2026/9/1 三嶽)
- 日本語を書く前に ng-words スキルを読む
- AIが書けるのはロードマップの「タスク候補」タブだけ。人の表は触らない
- SSOTはHILなしで書かない(CLAUDE.md参照)
- **カレンダーには書き込まない(2026/8/29 三嶽。二度目の指摘)。** 無人実行でも対話セッションでも同じ。
  Slack同期で触ってよいのはSSOTとロードマップだけ。日程は④として報告に出すところまでで、
  予定の作成・変更・削除はしない。カレンダーに入れるのは、三嶽が gcal スキルで別途指示したときだけ
