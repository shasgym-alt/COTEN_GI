# SSOTの変更チェック

ドライブ直下(`00_Company_Core`)をルートとして、前回チェック以降に変更されたファイルを探し、SSOT.xlsxに反映すべきものがあれば候補を出す。

## 大原則

1. **AIは候補しか作らない。** SSOTも既存文書も書き換えない
2. **ファイルを移動・削除しない。** このスキルは読むだけ
3. **日本語を書く前に `ng-words` スキルを読む**

## 手順

### 1. 前回チェック時刻を読む

前回時刻は各自のMacの `~/.claude/ssot-check/last_run.txt` にある(`YYYY-MM-DD HH:MM:SS` 形式)。無ければ24時間前を使う。今回の開始時刻を控えておく(手順6で保存する)。

### 2. 変更ファイルを洗い出す

ドライブ直下で実行する。

```bash
find . -type f -newermt "<前回時刻>" \
  ! -path "*/89_作業中/*" \
  ! -path "*/889_Claude_Code/*" \
  ! -path "*/.claude/*" \
  ! -path "*/old/*" \
  ! -name "~\$*" ! -name ".DS_Store" ! -name "*.tmp"
```

除外する理由: `89_作業中` は依頼どおり対象外。`889_Claude_Code` と `.claude` はツール・スキル置き場でSSOTと無関係(このスキルが出す提案ファイルもここに入るため、除外しないと翌日また検出してしまう)。`old/` は旧版の退避先。`~$` はOfficeのロックファイル。

### 3. SSOT.xlsx自体が変わっていたら

変更一覧に `SSOT.xlsx` があれば、誰かが直編集している。スナップショットを取る。

```bash
python3 889_Claude_Code/tools/ssot_tool.py dump
python3 889_Claude_Code/tools/ssot_tool.py diff
```

diffの内容(どのシートの何が変わったか)を報告に含める。dumpは読むだけなので承認なしで実行してよい。buildは実行しない。

### 4. 変更ファイルを読んで判定する

変更された各ファイルを読み(xlsx・docx・pdfは対応スキルで)、SSOTに関わる内容かを判定する。

- 決定事項、方針の変更、案件の追加・状況変化、数字の更新 → 候補にする
- 単なる体裁直し、途中の下書き、受領しただけの資料 → 候補にしない。ただし一覧には載せる
- 判定には先にSSOT.xlsxを読む。**すでにSSOTにある内容は候補に入れない。** 食い違っていたら食い違いとして出す

### 5. 論点台帳の重複チェック

論点台帳は行を書き換えて育てるため、放っておくと同じ判断が2行に分かれる。**週に1回(月曜の実行時)と、論点を5件以上足した直後に行う。** 台帳を全行読んでから、下の8項目を上から順に見る。

| # | 見るもの | 引っかかる例 |
|---|---|---|
| 1 | 論点の重なり | 2行が同じ判断を含んでいる。または片方が決まればもう片方が自動で決まる(従属関係は論点2つではなく、論点1つ+タスク1つ) |
| 2 | 1行2論点 | 「今の答え」の中に決めることが2つ以上ある。片方だけ決着済み |
| 3 | 行の中の矛盾 | 同じセルに新旧の数字が併存している(経緯を末尾に残す運用の副作用) |
| 4 | 確定行と討議中行の矛盾 | 確定の文言が古く、後から討議中の行が逆のことを書いている |
| 5 | 参照の切れ | 関連列のI-ID・WBS IDが実在しない。片側からしか参照していない |
| 6 | 形式の乱れ | 未討議なのに「決めた日・場」が埋まっている / 確定なのに期限が残っている / 担当が未割当 / 同じ話題の論点が複数の領域に散っている |
| 7 | WBSとの二重管理 | 論点の中で決めることになっているものが、WBSに独立タスクとしても残っている |
| 8 | ontologyの追随 | `.claude/skills/ontology/SKILL.md` の「現在の割当」が最新のI-ID・タスクIDまで来ているか |

統合するか分けるかの目安は、**決める人と決める場が同じなら1行、違うなら2行**。期限が違うものは分ける。

出すのは統合案の表だけにする(シート・行・変更前 → 変更後)。**確定行を触る案には変更依頼(CR)が要る**ので、その旨を表に書く。書き込みはssot-updateの手順でHILを取ってから。

### 6. 候補ファイルを書く

候補が1件でもあれば `889_Claude_Code/reports/SSOT更新提案_<日付>.md` に書く(フォルダが無ければ作る)。形式はinboxスキルの候補ファイルと同じ。

```
## 論点台帳の更新候補(既存の論点は行を書き換える。新規はI-ID採番案を付ける)
| I-ID | 論点 | 状態(未討議/討議中/確定) | 今の答え | 決めた日・場 | 担当 | 期限 | 根拠ファイル |

## 既存の記載と食い違うもの
| シート | 現在の記載 | ファイルの内容 | 根拠ファイル |

## 案件シートへの追加・更新候補
| 案件 | 種別・規模 | 状況 | 位置づけ | 根拠ファイル |

## 論点台帳の統合案(手順5を行った回だけ)
| I-ID | 見つかったこと | 変更前 → 変更後 | CRの要否 |
```

どの表にも、根拠にしたファイルのパスを必ず書く。

### 7. 報告して、時刻を保存する

- 変更ファイルの一覧(パスと更新日時)
- 候補が何件、食い違いが何件、候補ファイルの場所
- 変更が無ければ「変更なし」と一言で終える

最後に、手順1で控えた開始時刻を `~/.claude/ssot-check/last_run.txt` に保存する(フォルダが無ければ作る)。

## やらないこと

- SSOT.xlsxを直接編集する(反映は人が行う)
- `ssot_tool.py build` を実行する
- ファイルを移動・削除する
- 決まっていないことを決定の候補に書く
