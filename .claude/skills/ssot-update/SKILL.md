# SSOTの更新手順

対象: ドライブ直下の `SSOT.xlsx`。シートは 使い方 / 基本 / 方針 / 案件 / 数字 / 分岐点と期限 / 論点台帳 / 変更依頼 / 食い違い / 資料一覧 / 定義と用語集(v7.0、2026/8/23。決定ログと未決事項は論点台帳に統合済み)。

## 絶対のルール

1. **書き込み前にHIL。** 変更内容の一覧(シート・行・変更前 → 変更後)をユーザーに見せ、明示的なOKをもらってから書く。ユーザーの指示で始めた編集でも省略しない
2. **無人実行(定期タスク・自動処理)はSSOTに書かない。** 候補ファイルを出すところまで
3. **決定の文言は論点台帳にだけ書く。** 変更依頼シートには作業の指示(どの行をどう変えるか)だけを書く
4. **同じ論点は行を増やさず、その行を書き換える。** 論点台帳・基本・方針・数字のどこでも同じ。古い経緯は「今の答え」の末尾に1〜2文で残す。行が増えるのは新しい論点・新しい資料・新しい案件のときだけ
5. **状態は3値。** 未討議(案がまだ無い)/討議中(案や仮の値がある。旧「仮置き」)/確定(決めた日と場がある)。ステータスのセルは先頭にこの語を書き、補足は後ろ。色は 確定=緑(1E7B34)・討議中=橙(B45F06)・未討議=赤(C00000) の太字。確定を変えるときは討議中に戻して変更依頼を切る

## 手順

1. `~$SSOT.xlsx` ロックが無いことを確認する。あればExcelを閉じてもらう
2. 編集前に `889_Claude_Code/tools/ssot_tool.py dump` を実行(スナップショット)
3. 変更一覧を作ってユーザーに提示し、OKをもらう ← ここがHIL
4. openpyxlで直編集する。新しいセルのスタイルは隣接する行からcopyする(copy.copy(font/fill/border/alignment))
5. 「使い方」シートの更新履歴の先頭(A列が「日付」・B列が「版」の見出し行の直下にinsert_rows。行番号を決め打ちしない。2026/8/24に「直近の期限」表を削除して見出しは17行目になった)に日付・版(v6.7の次はv6.8)・内容を1行追記する
6. 保存後に再度 dump を取る
7. 承認するのは三嶽だけ(論点台帳 I-034「SSOTの更新責任者は三嶽」)。どのシートでも、三嶽のHILが取れていれば書いてよい。ほかの創業者の承認は要らない。ただし基本と定義・方針・分岐点と期限は決定そのものを変える重い変更なので、変更前後を並べて見せてから書く

## 決めごとの反映先

- 決めること・決まったこと → 論点台帳(I-ID | 領域 | 論点 | 状態 | 重要度 | 今の答え | 決めた日・場 | 担当 | 期限 | 関連)。新しい論点は未討議か討議中で登録してI-IDを採番(ontologyスキル)。重要な論点だけ重要度列に「重要」と書く(黒太字。それ以外は空欄)。決まったら同じ行の状態を確定にし、決めた日・場を入れる。行は消さない。論点の接頭辞は2026/8/31にT→Iへ変更済み(旧T-###=現I-###)
- 資料間の不一致 → 食い違いシート
- 案件の追加・変更 → 案件シート(ID列はP-001〜の連番、事業種別列あり)

## 論点台帳を変えたら「直近の期限」タブを作り直す

論点台帳の状態・期限・担当を変えたら、ロードマップ・アクションプラン_v2の「直近の期限」タブ(確定していない論点を期限順に並べた一覧。2026/8/24新設)を最新のスナップショットから作り直す。タブは閲覧用で、手で直さない。生成は `889_Claude_Code/tools/roadmap_tasks.py` の `service()` を使い、タブの値をclear→updateする(確定は除く、期限順、状態列は討議中=橙・未討議=赤)。
